Exercise 1
Explain in your own words why the Waterfall method often goes wrong when building software.
Give two reasons.

Answer: Requirements can change. Making changes can be expensive since each stage must be completed before the next begins.
Problems are discovered too late in the project. Many problems may not be discovered until the end of the project when testing occurs.

Exercise 2
Pick two of the four values in the Agile Manifesto. For each one, give an example of what it could
look like in a real team.

Answer: 1. Individuals and interactions over processes and tools — People communicating and working together are more important than rigid procedures and tools. Example: It is generally better to communicate within the team during say a morning sprint rather than implementing a new quality control measure.
2. Working software over comprehensive documentation — Having software that actually works is more valuable than producing lots of documentation. Example: A team writing software and actually fixing bugs rather than writing a report about problems or bugs.

Exercise 7

that I can buy the same thing again.

The customer can view a list of their previous orders after logging in.
Each order displays the order date, items purchased, quantities, and total price.
The customer can select a previous order and add the same items to their shopping cart to buy them again.


Exercise 8
Write a Definition of Done for a team of four developers. Include at least five points.

A task or feature is considered Done when all of the following criteria are met:
1. Code completed: The code is written and follows the team's coding standards.
2. Code reviewed: At least one other developer has reviewed and approved the code.
3. Tests passed: All relevant automated tests pass, and new functionality has appropriate tests.
4. No known critical bugs: No known critical or high-priority bugs remain.
5. Documentation updated: Relevant documentation is updated to reflect the changes.
6. Integrated: The code is merged into the main branch without conflicts.
7. Acceptance criteria met: The feature meets all agreed acceptance criteria.
8. Tested by the team: The feature has been tested in a test environment and works as expected.
All four developers are responsible for following the Definition of Done. A feature cannot be considered Done until it meets all the agreed criteria.


Exercise 9
A team's Daily Scrum takes 45 minutes. Everyone stands facing the manager and reports what
they did. What is wrong, and what would you suggest?

The Daily Scrum should be limited to 15 minutes, but this meeting takes 45 minutes.
Team members report to the manager instead of collaborating with each other.
The focus is on what people did, rather than progress toward the Sprint Goal and identifying obstacles.
The manager appears to be controlling the meeting, but the Daily Scrum is an event for the Developers.

Exercise 10
Scrum or Kanban? Choose for each team and explain why.
a) A team building a new mobile app
b) An IT support desk
c) A team fixing bugs in a webshop that is already live

a) Scrum — A team building a new mobile app can work in two-week sprints, set goals, and deliver new features incrementally.

b) Kanban — An IT support desk receives requests continuously and needs to prioritize and handle tasks as they arrive.

c) Kanban — A team fixing bugs in a live webshop needs to respond to issues as they occur, rather than waiting for the next sprint.
